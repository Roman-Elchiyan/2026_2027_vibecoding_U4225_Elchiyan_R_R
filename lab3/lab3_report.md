## 2. Архитектура развёртывания

### 2.1. Компоненты и хранение

| Компонент | Размещение и назначение |
| --- | --- |
| Telegram-бот | Windows, Python `.venv`; обработка команд и поисковых сценариев |
| SQLite | Локальные пользователи, настройки, история, избранное, отзывы и журнал операций |
| Argos Translate, E5, Cross-Encoder | Локальные модели перевода и ранжирования |
| LiteLLM Proxy | Docker; персональные ключи, обращения к модели и контроль расходов; `127.0.0.1:4000` |
| PostgreSQL | Docker; ключи и расходы LiteLLM, постоянный том `litellm_data` |
| ngrok | HTTPS-туннель к локальному порту 8080 для webhook |

`scripts/prepare_services.py` формирует параметры сервисов в `runtime/`. PostgreSQL получает параметры базы, LiteLLM — ключ провайдера и настройки Proxy. Telegram-токен используется процессом бота. PostgreSQL доступен во внутренней сети Docker. Секреты, базы, журналы, модели и кеши исключены из Git.

### 2.2. Транспорт Telegram

В режиме **polling** приложение получает обновления исходящими запросами к Telegram. В режиме **webhook** Telegram отправляет обновления по HTTPS через ngrok. Перед регистрацией webhook проверяются туннель и целевой порт; запрос защищён случайным путём и заголовком `X-Telegram-Bot-Api-Secret-Token`.

При недоступности туннеля предусмотрен переход в polling. Перед polling прежний webhook удаляется с `drop_pending_updates=False`. Полученные update ID учитываются в SQLite, действия пользователя сериализуются, файловая блокировка ограничивает запуск одним экземпляром приложения.

### 2.3. Запуск и эксплуатация

`scripts/run.ps1` подготавливает сервисы и запускает `bot.py --stage lab3 --external`. Параметр `-AI` включает ИИ в конфигурации и запускает Docker Compose с ожиданием готовности сервисов. Для этого режима требуется запущенный Docker Engine.

```powershell
docker version
.\scripts\run.ps1 -Mode polling -AI
```

Для webhook используется `-Mode webhook -AI`. Команды `/status`, `/ai`, `/limits` и `/admin` показывают состояние приложения и настройки доступа.

Журнал `runtime/logs/bot.log` использует UTC и ротацию 5 MiB с тремя архивами. События включают ошибки источников, обращения к ИИ, бюджетные операции, отзывы и переключение транспорта. `scripts/service_status.py` формирует диагностику сервисов с маскированием секретов.

## 3. Администрирование и обратная связь

### 3.1. Административные функции

Доступ к `/admin`, callback и текстовым административным действиям проверяется по `ADMIN_TELEGRAM_IDS`. Панель содержит состояние сервисов, список пользователей, блокировку доступа, разрешение ИИ, паузу новых поисков, управление E5, заявки на бюджет и отзывы. Избранное и `/limits` доступны при паузе поиска.

### 3.2. Персональные бюджеты и заявки

Пользователь получает virtual key LiteLLM с начальным бюджетом **$0.50**. PostgreSQL хранит ключи и расход, SQLite — настройки и журнал операций. `/limits` читает `max_budget` и `spend`; при недоступности Proxy остаток отображается как неизвестный.

Увеличение бюджета выполняется в два этапа: подготовка операции с пользователем, суммой, старым и новым лимитом, затем подтверждение администратором. Операция имеет постоянный UUID. При неопределённом результате HTTP выполняется сверка лимита в Proxy; повторное подтверждение не создаёт второе увеличение. Заявка пользователя содержит сумму и комментарий; администратор одобряет или отклоняет её с ответом автору.

### 3.3. Форма обратной связи

`/feedback` открывает форму с категориями «Работа бота», «Результаты поиска» и «Конкретная публикация». Можно выбрать несколько категорий и публикаций, добавить общий комментарий и необязательную оценку 1–5. Общий отзыв о боте доступен без предварительного поиска.

До отправки данные находятся в черновике. Кнопка «Отправить отзыв» создаёт одну запись для выбранных категорий; повторное нажатие не дублирует её. При редактировании сохраняются ID, ответ администратора и история изменений. Миграция `lab_schema=4` переносит прежние отзывы и оценки. Очистка истории поисков не удаляет отзывы.

### 3.4. Обработка и ИИ-анализ отзывов

Администратор просматривает категории, комментарии, оценки и связанные материалы, отмечает обработанные записи и отвечает автору. ИИ-анализ запускается после подтверждения и использует служебный бюджет. В модель передаются выбранные отзывы и сохранённый контекст результатов. Идентификаторы пользователей исключаются, типовые контакты маскируются правилами обработки текста.

Результат анализа содержит рекомендации. Автоматическое применение изменений к коду, доступу и бюджетам не предусмотрено. Ответ, стоимость, usage и ID запроса записываются в журнал ИИ-вызовов.

## 6. Выводы

Реализовано локальное развёртывание Telegram-бота с LiteLLM и PostgreSQL, поддержкой polling и webhook. Администратор управляет доступом, бюджетами, заявками и отзывами. Дубли обновлений Telegram отсеиваются, события обработки записываются в журнал.

Функциональные и интеграционные проверки подтвердили сохранение данных, защиту административных действий, учёт расходов и доставку команд через webhook. Условия запуска и диагностика описаны в [инструкции развёртывания](../docs/lab23_operations.md).
