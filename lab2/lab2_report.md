## 1. Цель и архитектура

В [Telegram-боте «Brilliant» detective](https://t.me/itmoftmi_err2026_bot) реализованы поиск по внешним источникам, перевод метаданных, дополнительное ранжирование и платная оценка релевантности. Локальный каталог PLOS Water из 434 публикаций и исходный режим `--stage lab1` доступны вместе с новыми функциями.

Поисковый конвейер: **запрос и фильтры → поисковые формулировки → API источников → объединение метаданных → строгие фильтры → ранжирование → оценка соответствия → сохранённая выдача**. Telegram-обработчики находятся в `lab_handlers.py`, основной сервис — в `research.py`, адаптеры — в `external_sources.py` и `statistics_sources.py`.

SQLite хранит настройки, историю, избранное, кеш и результаты проверки релевантности. Базовая схема Lab 1 сохраняет `PRAGMA user_version=2`; расширение Lab 2/3 использует `app_settings.lab_schema=4`. Карточки конкретной выдачи записываются в `result_payloads`, выбранные версии избранного — в `favorite_payloads`. Миграции сохраняют существующие данные.

## 2. Источники и способы поиска

| Источники | Данные и назначение |
| --- | --- |
| PLOS Water CSV | Локальный каталог: FTS5/BM25, RapidFuzz, Multilingual E5 Small |
| OpenAlex, Crossref, DataCite | Научные метаданные, тематический поиск, названия и точный DOI |
| PubMed/PMC, Europe PMC | Биомедицинские публикации; DOI, PMID и PMCID |
| arXiv | Препринты и поиск по идентификатору arXiv |
| Zenodo | Публикации и исследовательские данные; сведения о версиях |
| CORE | Поиск научных материалов через отдельный адаптер |
| World Bank Documents & Reports | Аналитические документы и описания |
| OECD, IMF, Eurostat, ILOSTAT, UN Comtrade | Статистические каталоги, наборы и ряды данных |
| Unpaywall и PMC ID Converter | Дополнение сведений о доступе и сопоставление идентификаторов |

CORE, OECD и UN Comtrade подключены как внешние API, а не как локальные базы. Наличие адаптера не гарантирует ответ сервиса в каждом запуске: доступ зависит от ключей, сетевого соединения и ограничений провайдера. Ранее для CORE наблюдался таймаут, для OECD — HTTP 403; новая проверка их доступности 20.10.2026 не выполнялась.

Поддерживаются тематический поиск, поиск по названию, DOI, PMID, PMCID и arXiv ID. Для точного идентификатора сохраняется соответствующая запись; тематические модели и платная оценка не подменяют такой результат другими публикациями. Поисковые выражения обрабатываются с учётом синтаксиса выбранного источника.

Пользователь задаёт источники, годы, тип материала, категорию, язык оригинала, доступность, объём подборки и сортировку. Неизвестные значения не проходят ограничивающий фильтр. Для статистики отдельно задаются территории, измерения и ключ ряда; статистические записи обрабатываются отдельно от публикаций.

## 3. Получение метаданных и устранение повторов

`MetadataHTTP` использует `httpx`, кеш SQLite на один час, не более трёх одновременных HTTP-запросов и общий предел 48 обращений на поиск. Поисковый сервис ограничивает время получения и обработки кандидатов 35 секундами. Для временных ошибок предусмотрен один ограниченный повтор с учётом `Retry-After`; уже полученные страницы сохраняются при сбое следующей страницы или другого источника.

Совпадающие нормализованные DOI объединяются с сохранением происхождения метаданных. Связанные версии Zenodo объединяются по `conceptdoi` и явным отношениям DataCite/Zenodo: `IsVersionOf`, `HasVersion`, `IsNewVersionOf`, `IsPreviousVersionOf`. Совпадения названия и аннотации при разных несвязанных DOI недостаточно для объединения.

Версии объединяются **после фильтров по году, языку и доступу**. Выбирается последняя подходящая версия с собственными DOI, аннотацией и ссылками. Все связанные DOI сохраняются в `version_dois`; сведения о версиях и источниках остаются в метаданных. Точный поиск старого DOI возвращает запрошенную версию. Сохранение в избранное и повторное открытие SQLite сохраняют выбранную карточку.

На реальном примере DataCite записи `10.5281/zenodo.11442546`, `10.5281/zenodo.11442547` и `10.5281/zenodo.11442728` объединены в одну работу. Для выдачи выбран DOI `10.5281/zenodo.11442728`; остальные DOI сохранены.

## 4. Перевод и локальные модели

Argos Translate использует установленные пары ru→en и en→ru. Русский запрос переводится для лексического поиска, а многоязычные модели получают исходный запрос. Перевод названия и аннотации доступен отдельно; библиографические идентификаторы и ссылки сохраняются. Переводы кешируются, вычисления выполняются вне цикла обработки Telegram.

Multilingual E5 Small (`intfloat/multilingual-e5-small`, 384 измерения) формирует семантических кандидатов. Cross-Encoder `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` сравнивает пары «запрос — название и аннотация» и уточняет порядок первых кандидатов. Обработка длинных аннотаций использует окна, ограниченные токенизатором. Модель загружается из локальных файлов; при недоступности или таймауте сохраняется резервный поиск.

Результаты разделяются по подтверждённому и частичному соответствию задаче. Отсутствующие в метаданных аспекты не считаются доказанными. Необработанное число Cross-Encoder не выводится как процент релевантности; пороги классификации применяются только при совместимой калибровке.

20.10.2026 на Windows прошли шесть тестов реальной E5 и один тест реального Cross-Encoder за **19,418 с**. Во время прогона сетевое скачивание моделей было отключено через `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`.

## 5. Роль платного ИИ

Платный ИИ вызывается через локальный LiteLLM Proxy с персональным virtual key. В конфигурации `research-basic` соответствует `openai/gpt-6-luna`. Алиас `research-complex` настроен для `openai/gpt-6.1-sol`, но пользовательский вызов резервной модели заблокирован в текущем коде.

Для платного поиска нужны разрешение конфигурации, доступ пользователя, включение через `/ai` и отдельный переключатель «ИИ-поиск». Само разрешение ИИ не запускает платную оценку каждой выдачи.

| Этап | Действие ИИ |
| --- | --- |
| План запроса | Формирует до трёх английских поисковых формулировок с сохранением условий пользователя |
| Оценка результатов | Проверяет до восьми найденных кандидатов по полным названиям и полученным аннотациям; возвращает категорию соответствия и короткую выдержку |
| Объяснение публикации | Объясняет связь конкретной найденной публикации с запросом по её полному названию и аннотации |

Поиск материалов выполняют адаптеры источников. Внешний веб-поиск в платной модели не подключён. ИИ не создаёт дополнительные DOI и библиографические записи. Полная аннотация означает весь текст, полученный от источника, а не полный текст статьи.

Ограничение первых 300 символов аннотации для оценки и первых 2500 символов для объяснения удалено. Целые карточки объединяются в JSON-пакеты до **60 000 символов** с учётом инструкции. Большая подборка делится на несколько запросов; каждый проходит проверку бюджета и кеширование. Если одна карточка не помещается целиком, платный вызов отклоняется до отправки, используется бесплатный поиск. Скрытого обрезания входа нет.

Начальный бюджет — **$0.50** без автоматического сброса. `/limits` читает выделенный бюджет, расход и остаток из LiteLLM. Ответ, стоимость и usage сохраняются в `ai_calls`. Идентичный завершённый запрос берётся из кеша; автоматических платных повторов нет. Обычная кнопка «Повторить поиск» пропускает платный ИИ.

В предыдущей живой проверке один запрос через персональный ключ завершился HTTP 200. Стоимость **$0.0000038** совпала с расходом LiteLLM и записью PostgreSQL; остаток изменился с $0.50 до $0.4999962. Новые проверки полных аннотаций выполнялись через подменённый HTTP-транспорт без оплаты.
