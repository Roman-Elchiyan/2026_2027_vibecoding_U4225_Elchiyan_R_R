## 1. Цель и задачи

Цель работы — расширить [Telegram-бот «Brilliant» detective](https://t.me/itmoftmi_err2026_bot) поиском научных и аналитических материалов во внешних источниках. Реализованы поиск по теме, названию и идентификатору, фильтрация, перевод метаданных, оценка релевантности и платные ИИ-функции с персональным бюджетом.

Локальный каталог PLOS Water из 434 публикаций используется вместе с внешними источниками. Пользователь выбирает источники и условия поиска; результаты сохраняются в истории и доступны для добавления в избранное.

## 3. Реализация поискового конвейера

### 3.1. Запросы и фильтры

Тематический поиск использует исходный запрос и дополнительные поисковые формулировки. Поиск по названию учитывает точные совпадения и неоднозначность одинаковых названий. Для DOI, PMID, PMCID и arXiv ID выполняется проверка соответствия запрошенному идентификатору.

Пользователь задаёт источники, годы, тип материала, категорию, язык оригинала, доступность, объём подборки и сортировку. Запись с неизвестным значением поля не проходит ограничивающий фильтр по этому полю. Для статистики предусмотрены территории, измерения и ключ ряда; статистические результаты обрабатываются отдельно от научных публикаций.

| Этап | Операция |
| --- | --- |
| Подготовка | Разбор запроса и построение формулировок с учётом синтаксиса источника |
| Получение | Загрузка страниц API, нормализация и дополнение метаданных |
| Объединение | Удаление повторов с совпадающими идентификаторами |
| Фильтрация | Проверка года, языка, типа, категории и доступа |
| Выбор версии | Объединение связанных версий Zenodo и выбор подходящей записи |
| Ранжирование | E5, Cross-Encoder и проверка соответствия задаче; при включении — платная оценка |
| Сохранение | Запись выдачи и метаданных карточек в SQLite |

### 3.2. Ограничения HTTP-клиента

`MetadataHTTP` использует `httpx` и часовой кеш SQLite. Предусмотрены не более трёх одновременных HTTP-запросов и общий предел **48 обращений на поиск**. Время поискового конвейера ограничено **35 секундами**. Для временных ошибок допускается один ограниченный повтор с учётом `Retry-After`. При сбое следующей страницы сохраняются уже полученные записи.

### 3.3. Идентификация публикаций и версии Zenodo

Записи с совпадающим нормализованным DOI объединяются с сохранением источников метаданных. Версии Zenodo связываются по `conceptdoi` и отношениям `IsVersionOf`, `HasVersion`, `IsNewVersionOf`, `IsPreviousVersionOf`. Одинаковые названия и аннотации при разных несвязанных DOI рассматриваются как отдельные записи.

Объединение версий выполняется после строгих фильтров. Выбирается последняя подходящая версия с собственными DOI, аннотацией и ссылками; связанные DOI сохраняются в `version_dois`. Точный поиск старого DOI возвращает запрошенную версию. Снимок выдачи и избранное сохраняют выбранную карточку при повторном открытии базы.

### 3.4. Перевод и ранжирование

Argos Translate использует локальные пары ru→en и en→ru. Переведённый запрос применяется для лексического API-поиска, исходный — для многоязычных моделей. Название и аннотация переводятся отдельно от идентификаторов и ссылок. Переводы кешируются; вычисления выполняются вне цикла обработки Telegram.

Multilingual E5 Small (`intfloat/multilingual-e5-small`, 384 измерения) получает семантических кандидатов. Cross-Encoder `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` сравнивает пары «запрос — название и аннотация» и уточняет порядок кандидатов. Для длинных аннотаций используются окна, ограниченные токенизатором. Модели загружаются из локальных файлов; таймаут или недоступность модели включает резервный способ ранжирования.

Проверка релевантности учитывает объект исследования и заданные аспекты. Материалы распределяются по полному и частичному соответствию; отсутствующие в метаданных аспекты остаются неподтверждёнными. Оценка Cross-Encoder используется для ранжирования, а классификационные пороги — при совместимой калибровке.

## 4. Платные ИИ-функции

### 4.1. Роль модели

Бот вызывает модель через локальный LiteLLM Proxy с персональным virtual key. Алиас `research-basic` соответствует `openai/gpt-6-luna`. Вызов разрешается при включённой конфигурации ИИ, доступе пользователя, разрешении `/ai` и активном переключателе «ИИ-поиск» для тематического поиска.

| Функция | Вход и результат |
| --- | --- |
| Планирование | Запрос пользователя → до трёх английских формулировок с сохранением ограничений |
| Оценка релевантности | До восьми найденных публикаций → категория соответствия и короткая выдержка из метаданных |
| Объяснение публикации | Запрос, полное название и полученная аннотация → объяснение связи публикации с задачей |

Материалы поступают из API источников. Модель анализирует полученные записи; самостоятельный веб-поиск не подключён. Алиас резервной `gpt-6.1-sol` присутствует в конфигурации, пользовательский вызов этой модели отключён.

### 4.2. Передача аннотаций

Для оценки и объяснения передаются полные названия и весь текст аннотации, полученный от источника. Карточки формируются в JSON-пакеты размером до **60 000 символов** вместе с инструкцией. Большая подборка делится на запросы по границам карточек. Если одна карточка превышает предел, платный запрос отклоняется до отправки; пользователю остаётся бесплатная выдача.

### 4.3. Бюджет и повторные запросы

Начальный бюджет пользователя — **$0.50** без автоматического сброса. `/limits` получает выделенный бюджет, расход и остаток из LiteLLM. Ответ модели, стоимость, usage и ID ответа сохраняются в `ai_calls`. Завершённый идентичный запрос возвращается из кеша; автоматические платные повторы запрещены. Кнопка «Повторить поиск» выполняет бесплатный поисковый сценарий.
