## 1. Новый гибридный поисковый механизм

Замени текущий поиск, который требует буквального совпадения всех слов, на гибридный поиск из трёх компонентов:

1. **SQLite FTS5 + BM25** — полнотекстовый поиск по заголовкам и ключевым словам, с ранжированием по релевантности.
2. **RapidFuzz** — дополнительный поиск при опечатках и неточном написании.
3. **Multilingual E5 Small** — многоязычный семантический поиск по смыслу.

Объединяй результаты этих механизмов с помощью обоснованной схемы ранжирования, например Reciprocal Rank Fusion (RRF), с возможностью настройки весов. Не смешивай непосредственно BM25, косинусное сходство и оценки RapidFuzz без нормализации.

Контрольный запрос:

**«Водоснабжение и качество питьевой воды»**

Этот запрос в текущей версии возвращает пустую выдачу. После исправлений необходимо проверить, находятся ли действительно релевантные публикации в англоязычном CSV.

Для семантического поиска отдельный предварительный перевод на английский не требуется: E5 должна сопоставлять запрос и документы напрямую.

При отсутствии E5 допускается ограничение межъязыкового поиска, но бот должен продолжать работать и честно сообщать об ограничении.

Сохрани точный поиск DOI. DOI и DOI-ссылки обрабатывай отдельно, без семантической подмены другими публикациями.

Не выдавай перевод названия или полного текста статьи за функциональность E5: E5 — модель поиска, а не переводчик. Перевод материалов пока не реализуй, если это потребует отдельного тяжёлого компонента.

## 6. Управление семантическим поиском

Предусмотри возможность отключать E5 без остановки бота.

Реализуй:

- Конфигурационный переключатель семантического поиска.

- Измерение времени семантической обработки.
- Логирование времени, устройства CPU/GPU и ошибок без пользовательских секретов.
- Отдельную настройку предельного времени обработки.
- Возможность вручную включать и отключать E5 через существующую команду `/admin`, только для пользователей из `ADMIN_TELEGRAM_IDS`.
- Сохранение административной настройки после перезапуска.

Автоматическое отключение при превышении времени должно быть реализовано безопасно: не допускай бесконечного ожидания, бесконтрольного накопления задач или блокирования Telegram-бота. Если прервать уже выполняемое вычисление безопасно нельзя, используй ограничение очереди, пропуск семантического этапа для следующих запросов и подходящий механизм защиты.

Для Lab 2 зарезервируй отдельную возможность отключения семантического ранжирования **внешних API**, независимо от локального поиска.

В будущем схема обработки внешних результатов должна быть такой:

1. Получение публикаций через API.
2. Дедупликация.
3. Предварительный отбор ориентировочно 50–100 кандидатов.
4. Семантическое ранжирование только отобранных материалов, желательно пакетами.
5. Кеширование embeddings по стабильному идентификатору и содержимому.
6. При превышении времени — возврат обычной ранжированной выдачи без E5.

**Сейчас внешние API не подключай.** Только обеспечь возможность такого расширения без переписывания всей поисковой системы.

## 7. Оптимизация хранения данных в SQLite

Сейчас каждая поисковая выдача полностью сохраняет JSON всех найденных публикаций, что приводит к дублированию данных.

Исправь архитектуру хранения:

- В `search_results` храни ссылку на публикацию, `search_id` и позицию в выдаче.
- Избранное также должно ссылаться на единую запись публикации.
- Используй нормализованный DOI для дедупликации, когда он имеется.
- Сохрани исходные метаданные и связь публикаций с их источниками.
- Не теряй порядок результатов и поисковые параметры.
- Предусмотри дальнейшее подключение нескольких научных API.

Обязательно реализуй миграцию текущей схемы SQLite через `PRAGMA user_version`.

**Не удаляй существующую базу и не теряй историю, избранное, настройки и пользовательские данные.**

Миграция должна быть транзакционной и безопасной при повторном запуске. Проверь перенос старых записей, а не только работу новой чистой базы.

## 9. Исправление пагинации Telegram

Сейчас переключение страницы создаёт новые сообщения и повторно выводит отдельные карточки.

Требования:

- Кнопки «Назад» и «Следующая страница» должны обновлять существующее сообщение через `edit_message_text`.
- Не отправляй пять новых карточек при каждом перелистывании.
- Добавь кнопки «Подробнее» для открытия полной карточки конкретной публикации.
- В подробной карточке должны быть реальные доступные метаданные, DOI, ссылка на источник и управление избранным.
- Добавь возврат из подробной карточки на исходную страницу.
- Изменение состояния избранного должно обновлять интерфейс без создания лишних сообщений.
- Аналогично исправь пагинацию избранного.
- Проверяй владельца поисковой выдачи и права доступа при каждом callback.
- Сохрани работу кнопок после перезапуска.

Соблюдай технические ограничения Telegram: не более 4096 символов в тексте сообщения и 64 байт в `callback_data`.

Если пять подробных публикаций не помещаются, сокращай только представление карточек в общем списке, не исходные метаданные в базе.

## Изменения после первичного тестирования Lab 1

Пустая выдача русского запроса потребовала добавить многоязычный E5, FTS5/BM25 и RapidFuzz с объединением по рангам. DOI сохранён как точный отдельный путь. Дублирование JSON устранено миграцией SQLite 1 → 2: общие материалы, ссылки выдач/избранного, нормализованные DOI и происхождение записей. Добавлена настраиваемая очистка истории. Размножение сообщений при перелистывании заменено одним редактируемым списком с подробностями и возвратом. Проверяются владелец, устаревшие кнопки и ограничения Telegram.

Последующее тестирование выявило избыточный хвост поиска и повторения общих родительских рубрик PLOS в текстах E5. Введены пороги релевантности и компактное представление конечных тем без изменения исходного CSV и метаданных. Проверены реальные запросы, GPU-вычисления, миграция копии рабочей базы и откат при повреждённой записи. Также устранены гонка счётчиков параллельного чтения CSV и незакрытые соединения в тесте миграции под Windows.
