## Реальная база публикаций

Скачай без модификаций оригинальный `ploswater.csv` из проекта `openwashdata/washopenresearch`:
https://raw.githubusercontent.com/openwashdata/washopenresearch/main/inst/extdata/ploswater.csv

Путь: `data/ploswater.csv`. **Перед реализацией открой CSV, посмотри настоящие заголовки и несколько строк, проверь кодировку/разделитель**, затем адаптируй поля к фактической схеме. Не выдумывай названия колонок или аннотации. На момент составления задания репозиторий автора содержит этот файл размером около 950 КБ; количество реально загруженных записей определяй кодом, не захардкоживай. Сохрани `data/SOURCE.md`: организация/авторы, исходная ссылка, ссылка на проект, лицензия CC BY и требования атрибуции, фактическая дата скачивания, SHA-256 файла, commit/revision источника по возможности. Нельзя подменять неудачную загрузку вымышленными публикациями: при отсутствии CSV показывай диагностическую ошибку.

Универсальная модель `Material`: стабильный ID, вид материала, title, authors, year, doi, url, open_url, access_status, abstract_or_snippet, source, доступные исходные метаданные. Незаполненные значения оставляй пустыми/None. Не называй аннотацией текст, который не является аннотацией; не заявляй о полном тексте или проверенном открытом доступе без данных.

Универсальная модель `SearchFilters`: topic, material_types, year_from, year_to, language, open_only, scope, sort, ai_enabled. `SearchResult`: items, warnings, search_id, total_count. Сейчас реально работают тематические ключевые слова/заголовок, DOI и год, тип материала — при наличии соответствующих столбцов. Язык, открытый доступ, выбор внешних источников и прочие неподдерживаемые фильтры должны быть видны как параметры будущей версии, но ясно обозначены «пока недоступно» и не должны создавать ложное ощущение, что результат был отфильтрован. Если фильтр из CSV невозможно достоверно вычислить, не применяй догадок. При некорректном интервале годов дай понятную ошибку. Дедупликацию заложи по нормализованному DOI, затем по устойчивому ID, без склейки разных публикаций только по похожим названиям.

Основное меню: **«🔎 Поиск материалов»**, **«⭐ Избранное»**, **«🤖 ИИ-поиск»**, **«📊 Мои лимиты»**, **«📝 Обратная связь»**, **«❔ Помощь»**. Сценарий поиска: пользователь вводит запрос (тема/название/DOI либо ссылку `https://doi.org/...`), при желании задаёт диапазон лет и тип, нажимает «Искать», получает фактические карточки из CSV. На карточке показывай заголовок, авторов при наличии, год, источник, DOI/ссылку и доступные сведения; кнопки «Сохранить/Убрать из избранного», «Открыть источник», «Следующая страница/Назад» там, где это имеет смысл. ## Архитектура (простая, но расширяемая)

Файлы в корне:
- `bot.py` — Application на `python-telegram-bot`, polling, подключение обработчиков, глобальный обработчик ошибок, логирование stdout и `runtime/logs/bot.log`;
- `config.py` — чтение `.env`, режим/флаги включения, ADMIN_TELEGRAM_IDS, SQLite путь, параметры поиска; для Lab 1 необходим только BOT_TOKEN (и ADMIN_TELEGRAM_IDS для админ-функций);
- `db.py` — SQLite, инициализация и **версионирование схемы** `PRAGMA user_version` для безопасных расширений; таблицы users, settings, searches, search_results, favorites; таблицы feedback/limit_requests можно заложить как минимальную схему, если это не усложняет реализацию;
- `handlers.py` — общие команды, кнопки, FSM, формы фильтров, карточки, пагинация, избранное;
- `search.py` — модели `Material`, `SearchFilters`, `SearchResult`, маршрутизация поиска, фильтрация и дедупликация;
- `sources.py` — реальный адаптер CSV, интерфейс будущих внешних адаптеров (без вызовов API в Lab 1);
- `admin.py` — серверная проверка прав и /admin с диагностикой; позже расширится;
- `ai.py`, `budget.py` — либо короткие явно отключённые адаптеры со стабильными интерфейсами, либо документы-контракты; НЕ имитируй реальные вызовы и бюджеты;
- `requirements.txt`, `.env.example`, актуализированный `.gitignore`, `data/SOURCE.md`, `tests/test_core.py`, `lab1/lab1_report.md`, `lab1/prompts.md`, `lab1/evidence/` (папку фиксируй через `.gitkeep`, если нет скринов).

Не используй pandas, SQLAlchemy, веб-фреймворк или Docker для Lab 1; CSV читается стандартным `csv`, БД — `sqlite3`. HTTP нужен только на этапе получения исходного CSV (или скачай его обычной командой), не в сценарии локального поиска. Для Python зависимостей достаточно `python-telegram-bot`, `python-dotenv` и тестового инструмента при необходимости. Совместимые версии фиксируй после установки. Код понятный, типизированный там, где это помогает, с короткими комментариями. Избегай чрезмерных абстракций.

Конфигурация: пример `.env.example` без настоящих ключей; секреты `BOT_TOKEN`, будущие OPENAI_API_KEY, OPENALEX_API_KEY, LITELLM_MASTER_KEY и т.д. **никогда не должны попадать в Git, логи, README, результаты тестов или ответ**. `runtime/`, `.env`, `.venv/`, `__pycache__/`, `*.pyc`, локальные `*.db`, `*.log` игнорируются.
