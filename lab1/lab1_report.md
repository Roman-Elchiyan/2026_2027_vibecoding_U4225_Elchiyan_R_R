## 1. Проект и цель работы

**«Brilliant» detective** — [Telegram-бот @itmoftmi_err2026_bot](https://t.me/itmoftmi_err2026_bot) для поиска научных публикаций по теме, названию или DOI. В первой лабораторной реализован поиск по локальному каталогу PLOS Water; результаты содержат библиографические метаданные, ссылки на первоисточники и сохраняются в избранном. Интерфейс рассчитан на последующее подключение научных и аналитических API.

Цель работы — разработать действующего Telegram-бота на Python с помощью генерации и доработки кода средствами ИИ, организовать хранение данных и проверить пользовательские сценарии.

## 2. Организация разработки

Разработка выполнялась в **Visual Studio Code** с расширением **OpenAI Codex** в режиме **Agent / Local**. ChatGPT использовался для проработки архитектуры, формулирования технических требований и составления промптов. Сами промпты также разрабатывались и уточнялись с помощью ИИ; реализация кода, его исправление и запуск автоматических проверок выполнялись через Codex.

## 3. Данные и технологический стек

В качестве исходных данных использован открытый набор [PLOS Water](../data/SOURCE.md) проекта [openwashdata/washopenresearch](https://github.com/openwashdata/washopenresearch): **434 научные публикации** за 2022–2026 годы. Каталог содержит названия, DOI, даты публикаций, первый указанный автор, тип материала, журнал, ключевые слова и другие доступные метаданные. Данные распространяются по лицензии CC BY 4.0; исходный CSV сохранён без изменения.

| Компонент | Реализация |
| --- | --- |
| Telegram-интерфейс | Python 3.13, `python-telegram-bot` 22.8; long polling |
| Хранение данных | SQLite: пользователи, настройки, публикации, история выдач, избранное |
| Полнотекстовый поиск | SQLite FTS5 с ранжированием BM25 |
| Поиск с опечатками | RapidFuzz |
| Семантический поиск | `intfloat/multilingual-e5-small`, 384-мерные embeddings |
| Вычисления модели | PyTorch 2.6.0 + CUDA 12.4, NVIDIA GTX 960; резервное выполнение на CPU |
| Конфигурация и журналирование | `.env`, `python-dotenv`, `logging`, ротация логов |

## 4. Архитектура и реализованные функции

Приложение построено по схеме **Telegram → обработчики → поисковые сервисы → SQLite → выдача результатов**.

| Файлы | Назначение |
| --- | --- |
| `bot.py`, `handlers.py` | Запуск polling, команды, формы поиска, сообщения, кнопки и навигация |
| `search.py`, `semantic_search.py` | Полнотекстовый, нечёткий и семантический поиск; объединение ранжирований |
| `sources.py` | Чтение и проверка локального каталога CSV |
| `db.py` | SQLite, миграции схемы, результаты поиска, избранное и история |
| `admin.py`, `config.py` | Проверка административных прав, настройка E5, конфигурация |
| `benchmark_search.py`, `tests/` | Измерение производительности и автоматические тесты |

**Поиск.** DOI сопоставляется точно. Тематические запросы обрабатываются FTS5/BM25, RapidFuzz и E5. E5 сопоставляет русскоязычный запрос с англоязычными заголовками и ключевыми словами без предварительного машинного перевода. Итоговый порядок формируется методом взвешенного **Reciprocal Rank Fusion (RRF)**; фильтры года и типа применяются ко всем кандидатам.

**Кеширование и устойчивость.** Векторы 434 публикаций рассчитываются при построении индекса и сохраняются в `runtime/semantic/`. При обычном запросе кодируется только запрос. Для E5 предусмотрены таймаут, переход CUDA → CPU и резервный поиск FTS5/RapidFuzz. Администратор может включать и отключать семантический поиск через `/admin`; настройка сохраняется в SQLite.

**Хранение.** Схема SQLite обновлена с версии 1 до версии 2 с переносом существующих данных. Метаданные публикаций хранятся централизованно, а результаты поиска и избранное ссылаются на идентификаторы материалов. История ограничена 50 выдачами на пользователя и сроком 30 дней; избранное сохраняется.

**Интерфейс.** Реализованы `/start`, `/help`, `/search`, `/saved`, `/cancel`, `/status`, `/admin`. Выдача содержит по пять результатов на странице. Перелистывание, просмотр подробной карточки, возврат и управление избранным редактируют существующее сообщение Telegram. Доступ к пользовательским выдачам и административным действиям проверяется сервером.

## 5. Тестирование

Проведены автоматические тесты, диагностика приложения, измерения производительности и ручная проверка в Telegram.

| Проверка | Результат |
| --- | --- |
| Автоматические тесты `unittest`, включая реальную E5 и миграцию SQLite | **70 из 70 — успешно** |
| `bot.py --check`, `pip check` | Успешно |
| Индексация 434 публикаций | 2,047 с |
| Загрузка готового индекса | 0,044 с |
| Повторный гибридный поиск | 0,10–0,12 с |
| Русский запрос «Водоснабжение и качество питьевой воды» | **20 результатов** вместо нуля в первой версии |
| Поиск DOI `10.1371/journal.pwat.0000423` | Одна соответствующая публикация |
| Избранное `/saved` | Сохранённая публикация отображается |
| Навигация по выдаче | Проверена страница 2 из 4; список отображается в одном сообщении |
| Семантическая модель | Работа на GTX 960 подтверждена вычислениями CUDA |

Автоматические проверки охватывают точный поиск DOI, фильтры, опечатки, межъязыковую релевантность, создание и повторное использование индекса, переключение E5, таймауты, разграничение прав, миграцию и целостность SQLite, сохранение избранного и Telegram-навигацию. Ручная проверка в Telegram включала тематический русскоязычный запрос, перелистывание результатов, поиск конкретного DOI и просмотр избранного.

Подробные параметры, контрольные запросы и замеры приведены в [технических заметках по гибридному поиску](../docs/hybrid_search.md). Протокол первоначальных проверок сохранён в [lab1/evidence/local_checks.md](evidence/local_checks.md).
